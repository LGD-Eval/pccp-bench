# 外部实跑协议 v1（PCCP-Bench 0.1.3）

目的：把"隐藏列从未被外人跑过"这条缺口（外部 AI 与自家审查都点了名）用一个可执行的流程补上，
而不是靠一句"欢迎来跑"。协议的目标是：**别人不需要联系我们，也能在公开列得到可复算的分数；
隐藏列则由我们代跑，并交回逐题成绩文件。**

## 1. 对外可立即自助的部分（不需要我们点头）

```
curl -L -o p.zip https://zenodo.org/records/24551199/files/pccp-bench_zenodo_v0.1.3.zip
sha256sum p.zip          # 应为 5151fe7ffa48be46ad55201bf334b536320535805363fa81c3f93a809d942b83（0.1.3）
unzip p.zip && cd p
python -c "import hashlib,json;m=json.load(open('MANIFEST.json'));print(all(hashlib.sha256(open(f['archive_path'],'rb').read()).hexdigest()==f['sha256'] for f in m['files']))"
cd dataset && python bench.py --submit your_adapter.py --team yourname
```

你会拿到：`public` 精确匹配、`masked` 精确匹配、`tag` 命中率、`macro_recall`、空基线对照、类别分布。
`hidden` 在公开包里是 `n/a`——这是设计，不是缺陷。

## 2. 隐藏列代跑（我们跑，你看逐题结果）

1. 你提交：`adapter.py`（实现 `evaluate(ctx) -> {"verdict": "...", "tag": "..."}`）+ 队名 + 许可声明（允许公开你的分数与免责声明）。
2. 我们在**离线环境**跑：`python bench.py --submit adapter.py --team <队名>`，隐藏列与公开列各一份成绩。
3. 交回三件：`score_*.json`（逐题行 + 摘要）、控制台日志、以及 `--verify` 在你那份文件上的输出。
4. 你可用 `python bench.py --verify <score>.json` 复核公开列；隐藏列因含未公开题，只能由我们复核并给出摘要。

**不承诺**：不给隐藏题、不给隐藏题答案、不给"你差在哪几题"的逐题反馈（那等于泄题）。
**承诺**：48 小时内回结果；分数好坏不删不改；你若要求匿名，只公开队名哈希。

## 3. 提交前请自检的四件事（避免无效跑）

| 检查 | 命令/标准 |
|---|---|
| 适配器不依赖本机绝对路径 | 在一台没装 `lgd_engine` 的机器上跑一次 `--submit` |
| 不改题、不读 `evidence/scores/*` 当答案 | 代码里不出现对 `cases_public.json` 的写操作、不读 `expected_verdict` |
| 返回合法标签 | `verdict ∈ {go, reject, hold}`，`tag ∈ 六词表` |
| 有确定性 | 同输入两次运行结果一致（随机因素请固定种子） |

## 4. 反照（防止"跑通即正义"）

每次外部提交，我们同时跑三个对照：

1. **参考实现**：应得 `public 0.9688 / masked 0.9688 / tag 1.0`。
2. **背题者**：应得 `public 1.0 / masked 0.125 / tag 0.0312`——如果背题者在 masked 列不掉，说明掩码规则坏了。
3. **空基线（一律 go）**：`exact 0.875 / macro_recall 0.5`——如果某人分数低于它，说明适配器有问题而不是"很难"。

三者任一异常，当次外部跑分作废并先修台子。

## 5. 时间线与对外口径

| 阶段 | 内容 | 对外能说什么 |
|---|---|---|
| 现在 | 邀请 1–3 队做首轮外部实跑 | "公开列自助可跑；隐藏列代跑开放申请" |
| 首轮完成 | 有 1 份外部成绩进台账 | "已有 1 队外部实跑（队名/匿名哈希）" |
| ≥3 队 | 可谈"多队可比" | 仍需注明"样本量小、非排行榜" |
| 补题到 60 + κ + 专家签字 | 才谈论文级 | 现在不谈 |

## 6. 记录什么（台账字段）

`提交日期 / 队名或哈希 / 适配器 sha256 / 公开列三数 / 隐藏列三数 / 与基线关系 / 是否复跑一致 / 备注`
每次记录同步进 `standings` 台账（本地 JSON + 对外仓一份 md 摘要），**不删历史记录**。

## 7. 边界（写进协议，不留在口头）

- 我们不因外部成绩而改题；改题只能由"新题"承载（旧题冻结）。
- 我们不把外部成绩当作"通过认证"；它是台子上的一个数。
- 若外部适配器读到隐藏题的间接线索（如 `hidden_commitment.json` 里的 id），该次作废重跑。
