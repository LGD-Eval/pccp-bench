盲标材料：`annotation/blind_kit/`（37 张单子 + 一张空 CSV）。**先做完，再读本协议第 3 节之后的内容。**

## 1. 你要判的唯一一句话

> **这次变更，被该器械已获授权的 PCCP 覆盖了吗？**

判的是**文本**，不是临床价值、不是器械好坏、不是 FDA 会不会批。你手里只有：器械、变更、决策文件里那一段原句、以及 PDF 链接。

## 2. 四条规则（来自我们的 `DECISION_reject_vs_hold.md`，你可以不接受，但要照它执行并留痕）

| 类 | 判定条件（全部成立才是这一类） | 常见错法 |
|---|---|---|
| `go` | 计划里有明确表述覆盖这类变更，**且**计划为这类变更是写明的验收判据都被本次描述满足 | 因为"看起来无害"就判 go |
| `hold_insufficient` | 变更在计划范围内，但必要步骤、判据、验证没做或没说清 | 把"计划没写"误当成"计划不允许" |
| `hold_resubmit` | 计划**没有覆盖**这类变更 → 必须另交新申报 | **把"没覆盖"直接判成 reject**（这是 v1 错的地方） |
| `reject` | 禁止性行为：拿修改版当 predicate、没有 PCCP 却宣称覆盖、§515C(c) 那类 | 把"越界"当"禁止" |

**为什么"越界"是 hold 不是 reject**：§515C(b) 的字面是"若变更与已授权 PCCP 一致，则不需要新的上市前通知"，它规定的是**免于新申报的条件**，不是"不一致即不许做"。不一致的后果是**必须另交**，而不是**禁止**。你可以反对这个读法，但请照此标注并在 comment 里写明你的反对，我们会把它单独列出来。

## 3. κ 怎么算（预先写死，防事后调参）

- **主指标：二分类 κ** —— `覆盖（go，且判据满足）` vs `不覆盖（其余三类）`。原因：37 题里 `reject` 为 0，四类直接算 κ 会出现稀疏格，数值不稳。
- **次指标：四分类 κ**（`go` / `hold_insufficient` / `hold_resubmit` / `reject`），只作补充，不单独下结论。
- **门槛（现在写死，不随后续结果改）**：
  - κ < 0.40 → **改协议**（不是改题，也不是改我们的标签）；
  - 0.40 ≤ κ < 0.60 → 报告为"中等一致"，对外只能说"存在解释差异"；
  - κ ≥ 0.60 → 才可以写"实质一致"。
- 计算脚本：`annotation/kappa.py`（零依赖，含 selftest）。双方填完 CSV 后：

```bash
python annotation/kappa.py --a blind_answers_A.csv --b blind_answers_B.csv
```

## 4. 污染与作废

- 做完之前看了 `candidate_pool/*.json`、`CANDIDATES_TABLE.md`、`DISAGREEMENT_37.md`、任何含 `expected_verdict` / `judge` 的文件 → 视为污染，**先声明再重做**，否则整份作废。
- 每题必须引一句你自己在 PDF 里搜到的原句；引不到写 `evidence_missing`。**不带原句的答案不收，这条对我们自己的标注也一样。**

## 5. 分歧会被怎么处理

- 逐条公开（题号 + 双方标签 + 双方原句），进 `candidate_pool/DISAGREEMENT_*.md`。
- 不为了"好看"改任何一方；分歧本身就是这套台子要测的东西。
- 若分歧集中在某一条规则上（例如"越界算不算禁止"），那说明缺的不是标注人，而是**判据需要专家签字认定**——我们会照实写进发布前审查。
